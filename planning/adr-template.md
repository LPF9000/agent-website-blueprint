# ADR NNNN: Decision title

Date: YYYY-MM-DD. Status: proposed / accepted / superseded. Owner: identify. Related requirement/task: ID.

## Context

What concrete user need or constraint forces a choice? Include traffic/data assumptions, security boundary, budget and existing architecture.

## Options

Compare the simplest option and at least one realistic alternative by maintenance, cost, compatibility, accessibility, security, portability and recovery.

## Decision and consequences

State the chosen approach, why it meets acceptance criteria, what is deliberately excluded, operational responsibilities, migration path and reversal conditions.

## Evidence

Official sources with reviewed dates and installed versions; executed checks with environment and outcomes. Distinguish source review from runtime testing. Link replacement ADR if superseded.
