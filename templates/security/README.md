# Header and preview templates

Copy [_headers](_headers) only after adapting it to actual site behavior. The CSP fits a small same-origin script/style policy; framework inline scripts/styles, data images, widgets and external calls will need reviewed hashes/nonces or narrowly allowed origins. Use Report-Only in preview during development, review violations and enforce the final tested policy before launch. Do not add unsafe-eval/blanket wildcards to hide failures.

HSTS starts at 300 seconds intentionally. Verify HTTPS across intended hostnames, then increase deliberately. includeSubDomains/preload are omitted because a generic template cannot establish their safety.

[preview-headers.txt](preview-headers.txt) is for an isolated preview artifact/config only. Add its noindex rule to preview static output and equivalent runtime middleware. Preview protection/authentication is still required for private content. Verify actual preview headers; robots.txt alone does not prevent indexing reliably. Remove noindex from intended public production pages.

Static header files do not cover responses generated by Worker/SSR handlers. Set runtime headers for HTML/API/errors/denials; private responses need no-store and exclusion from custom caches. CORS is omitted by default because same-origin sites need no cross-origin permission. Cookies are set by the chosen auth implementation with secure documented settings, not this file.

Verification: actual GET headers on HTML, assets, 404, redirects and APIs; browser CSP console; Auth/widget/payment journeys; private cache checks. Monitoring's presence checks cannot validate full CSP correctness.

Sources: [Cloudflare headers](https://developers.cloudflare.com/workers/static-assets/headers/), [OWASP CSP](https://cheatsheetseries.owasp.org/cheatsheets/Content_Security_Policy_Cheat_Sheet.html), [OWASP headers](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html).
