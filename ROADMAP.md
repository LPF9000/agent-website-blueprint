# Roadmap

The repository remains documentation-first. Changes should make a real workflow easier to follow or verify; a new framework/integration is not a reason to add infrastructure by itself. No delivery dates are promised.

| Work | State | Acceptance evidence |
| --- | --- | --- |
| Modular build/resume/review workflow and persistent state templates | Tested | Documentation integrity checks and linked examples |
| Generic operational failure modes and environment/release evidence | Tested | Cross-links, official references and release checklist |
| Small runnable static walkthrough | Tested locally | Reproducible build, artifact inspection and loopback HTTP checks; no hosted verification |
| Clear entry point, contribution forms and release boundaries | Tested | Internal links and parsed repository configuration |
| Framework-specific worked example, if a documented need warrants it | Not started | Locked dependencies, reproducible build and actual preview verification before claiming support |
| Broader accessibility/browser evidence for the runnable example | Not started | Named browser/device, keyboard/manual observations and relevant automated checks |

Propose a scoped change through the issue forms. Include the problem, the simplest useful change and its verification. Contributions should preserve generic examples, optional infrastructure and current-source review. Track implementation evidence in the relevant document rather than labeling unexecuted integrations complete.
